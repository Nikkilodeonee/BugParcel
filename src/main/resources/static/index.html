    How it works

    1. 1

      Record the browser side

      Export a HAR from your browser’s Network tab after reproducing the problem. Preserve request and response ID headers.

    2. 2

      Add the server side

      Import JSON, logfmt, Spring Boot, Logback/Log4j2, Python, Apache/nginx, or Docker JSON logs. Detected formats appear above the evidence. Shared IDs create confirmed links; optional time hints are guesses.

    3. 3

      Review, then share

      Inspect failed requests and redactions, then export HTML, Markdown or JSON. Nothing is saved between sessions; download before clearing or closing.

    Add request IDs

    Return X-Request-ID and write the same ID into your logs. Choose your stack, install the snippet, then record a new HAR and matching logs. This cannot repair old recordings.

    Framework API reference ↗

    Request IDs are diagnostic labels, never authentication. Validate inbound IDs or generate them at your trusted edge. Preserve the ID across proxies and downstream calls. For cross-origin browser code that reads the header, also expose X-Request-ID through your CORS configuration.
